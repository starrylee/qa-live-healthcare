# 后端架构文档

## 1. 架构概述

本项目采用**微服务架构**设计，基于 Spring Boot 3.x 构建，为在线医疗问诊平台提供后端服务支持。系统遵循**领域驱动设计 (DDD)** 思想，按业务领域划分为多个独立服务，每个服务可独立开发、部署和扩展。

### 1.1 架构目标

| 目标 | 说明 |
|------|------|
| **高内聚低耦合** | 按业务领域拆分服务，服务间通过 API 通信 |
| **可扩展性** | 支持水平扩展，应对流量增长 |
| **可维护性** | 清晰的代码分层，便于维护和迭代 |
| **高可用性** | 多实例部署，故障自动转移 |
| **安全性** | 统一的认证授权，数据传输加密 |

### 5.2 分层调用规则

```
规则说明:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 上层可以调用下层, 下层不能调用上层
   ✅ Controller ──► Service ──► Repository ──► Entity
   ❌ Entity ──► Repository ──► Service ──► Controller

2. 同层之间不直接调用
   ❌ ControllerA ──► ControllerB
   ❌ ServiceA ──► ServiceB (应通过业务编排)

3. 跨服务调用通过 HTTP Client
   ServiceA ──► HTTP Client ──► ServiceB API

4. DTO 用于层间数据传输
   • Controller: 接收/返回 DTO
   • Service: 处理 Entity, 转换 DTO
   • Repository: 操作 Entity
```

### 8.2 CORS 配置

```java
@Configuration
public class CorsConfig {
    
    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return new WebMvcConfigurer() {
            @Override
            public void addCorsMappings(CorsRegistry registry) {
                registry.addMapping("/api/**")
                    .allowedOrigins("*")                          // 允许所有来源 (开发环境)
                    .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                    .allowedHeaders("*")
                    .allowCredentials(false)
                    .maxAge(3600);                                // 预检缓存 1 小时
            }
        };
    }
}
```
